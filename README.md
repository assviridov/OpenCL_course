# OpenCL_course — практическое занятие: первое знакомство с вычислениями на GPU

Одно занятие (~70 минут), все задачи разбирает преподаватель; домашнее задание — задача
о фильтрации сигнала (ставится в конце; задание лежит в папке `student/`).

Сквозная идея занятия, одна на всё:

> **На CPU один исполнитель крутит цикл `for` по всем элементам.
> На GPU исполнителей столько же, сколько элементов, и у каждого цикл
> состоит из одной итерации. Номер своей итерации исполнитель узнает
> через `get_global_id()`.**

## Блок 1 (0–20 мин). Задача 1: сложение векторов

Запускаем `VectorSum` и `VectorSumCL` на одних данных — вывод совпадает.
Что показать и проговорить:

1. **Карта соответствия** (на доске):

   | CPU | GPU (OpenCL) |
   |---|---|
   | `for (int i = 0; i < N; i++)` | N work-item'ов, у каждого `int i = get_global_id(0);` |
   | тело цикла | тело ядра `__kernel` |
   | массивы A, B, C в RAM | буферы `cl_mem` на устройстве |
   | вызов `sum(...)` | `clEnqueueNDRangeKernel(...)` |
   | аргументы функции | `clSetKernelArg` (буферы — по указателю, скаляры — по значению) |

2. **Хост-код (функция main()) как рецепт из 4 действий:** положить данные → сказать ядру, с чем работать →
   сказать, сколько исполнителей, и запустить → забрать результат.

3. **Два таймера** в программе (полный цикл и только ядро по событию) и реальные замеры
   (Apple M2, 2026; все времена в консоли печатаются в наносекундах; в таблице те же
   числа в мкс):

   | N | CPU | GPU kernel only | GPU transfer + kernel |
   |---|---|---|---|
   | 25 | 0.001 мс | 0.14 мкс | 2.9 мс |
   | 1 000 000 | 0.74 мс | **8 мкс** | 3.3 мс |

   Обсуждение: ядро быстрее CPU-цикла на ~2 порядка, но полный цикл GPU-версии —
   медленнее: доминирует перенос данных. На 25 элементах всё съедают накладные
   расходы на запуск. Вывод: GPU выгоден при большой работе на один байт данных.

## Блок 2 (20–42 мин). Задача 2: сложение матриц

Одно новое понятие: **двумерная топология**. Всё остальное то же, что в задаче 1.

1. От CPU-цикла к ядру (обе версии в файле рядом):

   ```c
   // CPU: два вложенных цикла
   for (int i = 0; i < m; i++)         // строки
       for (int j = 0; j < n; j++)     // столбцы
           C[i*n+j] = A[i*n+j] + B[i*n+j];
   ```
   ```c
   // GPU: сетка M x N исполнителей, у каждого — одна итерация
   int col = get_global_id(0);   // внутренний цикл
   int row = get_global_id(1);   // внешний цикл
   int i = row * N + col;        // та же формула индексации!
   C[i] = A[i] + B[i];
   ```

2. **Индексация row-major** — вывести на доску: элемент (row, col) живёт
   в линейном массиве по адресу `row * N + col`.

3. **Матрица прямоугольная (8×5) — специально.** Если M=N, студенты часто
   «схватывают» индексацию неверно; разные M и N заставляют честно разобраться,
   какая размерность за что отвечает.

4. **Порядок размерностей запуска**: `size_t global[2] = {N, M}` — размерность 0
   (соседние номера отличаются на 1) отдана столбцам. Вопрос для проверки:
   «что произойдет, если поменять N и M местами?» (ответ: выход за границы /
   мусор в результате — у части элементов row*N+col укажет не туда).

5. Сверка выводов CPU и GPU построчно.

## Блок 3 (42–65 мин, резерв до 70). Постановка домашнего задания: фильтрация сигнала

задача дается в теме 7.1 как домашняя задача E
([полный текст — на Google Drive](https://drive.google.com/file/d/1DIYSqoxix0NiBAeg5-WPRO4PW2_66nW2/view)).

Код не пишем — только формулировка и декомпозиция на доске (по картинке из условия).
Упрощенная постановка для студентов (1 страница):

- Сигнал: N каналов, в каждом M отсчетов. К каждому каналу применяется «фильтр» —
  набор из K коэффициентов b (K нечётное). Скользящее окно размера K движется по каналу
  со сдвигом 1; в каждом положении считается сумма произведений отсчетов на коэффициенты
  (как скалярное произведение окна и фильтра). Окно не выходит за границы массива,
  поэтому отсчеты r, где окно не помещается, считаются нулями.
- Для разных каналов — разные фильтры: в отдельной строке для каждого канала
  указан номер набора коэффициентов (значения 1 или 2).
- Найти среднее арифметическое всех r по всем каналам (краевые нули входят в среднее!).

Вопросы для доски (студенты отвечают):

1. Сколько значений r вычислимо в канале? → **M − K + 1**; где они «сидят»? →
   индексы (K−1)/2 … M−1−(K−1)/2, по краям (K−1)/2 нулей.
2. Куда делись краевые элементы? → не вычисляются, но **входят в знаменатель** N·M.
3. Как разложить задачу по исполнителям GPU? → сетка (канал × позиция) — та же топология,
   что у матрицы из задачи 2; в каждой клетке — цикл по K.
4. Что сложнее, чем в задачах 1–2? → цикл внутри ядра; разные b для разных строк;
   вещественные данные (float); усреднение на CPU после суммирования результатов.

Формулировка ДЗ (двухчастная):

- **Часть A**: один канал, один фильтр, вывести весь массив r. Данные — пример из условия
  (M=5, K=3): ответ сверяется визуально с иллюстрацией.
- **Часть B**: полная задача — N каналов, выбор фильтра 1/2, среднее по всем N·M отсчетам.
- **Бонус**: сравнить две декомпозиции — «work-item на позицию» и «work-item на канал»
  (как в подсказке условия) — и объяснить, какая лучше для GPU и почему.

Раздается: папка **`student/`** целиком — README с постановкой, `example.txt`,
генератор `FilterGen`, эталон `FilterCheck`, шаблон `FilterCL`.

## Сборка

### Windows / Code::Blocks

1. Установите Code::Blocks **с компилятором MinGW** (инсталлятор `...mingw-setup.exe`).
2. Установите OpenCL SDK (например, [OCL_SDK_Light](https://github.com/GPUOpen-LibrariesAndSDKs/OCL-SDK/releases/download/1.0/OCL_SDK_Light_AMD.exe)) — путь из шага 3 подставьте свой.
3. Один раз для всех проектов: **Settings → Compiler → GNU GCC Compiler → Search directories**
   - вкладка **Compiler**: добавьте `<путь к SDK>\include` (`C:\Program Files (x86)\OCL_SDK_Light\include`)
   - вкладка **Linker**: добавьте `<путь к SDK>\lib\x86_64` (`C:\Program Files (x86)\OCL_SDK_Light\lib\x86_64`)
4. Откройте `OpenCL_course.workspace` — увидите все девять проектов сразу
   (проекты задач лежат в `task1_vectors/`, `task2_matrix/`, `task3_filter/`).
   **Выберите сборочную цель** (выпадающий список на панели инструментов):
   на Windows — `Debug`, на macOS — `Debug mac` (линковка OpenCL отличается:
   `-lOpenCL` на Windows, `-framework OpenCL` на macOS).
   Собрать всё: `Build → Build workspace`. Запустить: ПКМ по проекту → `Activate project`, затем `Build → Run`.
   CPU-проектам (`VectorGen`, `VectorSum`, `MatrixSum`, `FilterGen`, `FilterCheck`) библиотека
   не нужна — они собираются в любой цели.
5. Рабочая папка при запуске задана в `.cbp` как корень репозитория: `VectorGen`
   создаст `vector.txt` в корне репозитория, и остальные программы
   прочитают его оттуда. Папки `bin\`, `obj\` появятся внутри проектов — это артефакты сборки.
6. При запуске вне IDE Windows находит `OpenCL.dll` в `System32` (его устанавливает драйвер видеокарты).
